# Hardening and technical delivery

Trigger: A scoped remediation engagement or approved change.

Ownership: Keenan prepares and implements within authorization; Principal reviews changes and outcomes.

1. Link each proposed change to a finding and record exact assets, intended settings, dependencies/licensing, expected effect, owner, and window in changes.csv.

2. For each change record client authorization, Principal review, baseline evidence, pilot plan, rollback procedure, rollback triggers, and a verified recovery/access path.

3. Check current vendor documentation for the specific product, version, and tenant. Treat existing hardening checklists as planning references, not ready-to-run instructions.

4. Validate in a suitable test/pilot context, review results, then apply only the approved change within its window. Stop and escalate if scope, access, or observed impact differs.

5. Collect after-state evidence, test the agreed success criteria, document exceptions or rollback, and obtain review. A score increase alone does not prove risk is resolved.

Completion: Validated changes with before/after evidence, recorded exceptions, and client handoff.
